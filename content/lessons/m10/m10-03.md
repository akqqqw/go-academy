## Один тест — много случаев

Вместо копирования теста на каждый вход пишут таблицу:

```go
package calc

import "testing"

func Clamp(value, low, high int) int {
	if value < low {
		return low
	}
	if value > high {
		return high
	}
	return value
}

func TestClamp(t *testing.T) {
	cases := []struct {
		name     string
		value    int
		low      int
		high     int
		expected int
	}{
		{name: "в диапазоне", value: 5, low: 0, high: 10, expected: 5},
		{name: "ниже", value: -3, low: 0, high: 10, expected: 0},
		{name: "выше", value: 15, low: 0, high: 10, expected: 10},
		{name: "граница", value: 10, low: 0, high: 10, expected: 10},
	}

	for _, tc := range cases {
		t.Run(tc.name, func(t *testing.T) {
			if got := Clamp(tc.value, tc.low, tc.high); got != tc.expected {
				t.Errorf("Clamp(%d, %d, %d) = %d, ожидалось %d",
					tc.value, tc.low, tc.high, got, tc.expected)
			}
		})
	}
}
```

Ключевые элементы: имя случая (для `-run` и отчёта), все входы, ожидаемый
результат. Для ошибок добавляют поле `wantErr bool` или `wantErr error`.

## Почему это удобно

- Новый случай — одна строка.
- Провал сразу видно в имени: `TestClamp/ниже`.
- Сравнение легко автоматизировать (например, `cmp.Diff` или `reflect.DeepEqual`
  для структур).

## Границы

Обязательно включайте крайние значения: ноль, пустую строку, `nil`, максимум,
минимум. Ошибки — тоже случаи таблицы.

## Частые ошибки

- **Забыть `tc := tc`.** В Go 1.22+ не нужно, но в коде для старых версий без
  этого все подтесты видели последний элемент.
- **Безымянные случаи.** В отчёте не понять, какой вход сломался.
- **Слишком большая таблица без группировки.** Разделяйте happy path и ошибки.
- **`t.Fatalf` внутри подтеста без нужды.** `Errorf` даёт больше информации.

## Практика

**Задание.** Проверьте в `main` таблицей три случая функции `Sum(a, b int) int` и напечатайте число успешных.

**Стартовый код:**

```go
package main

import "fmt"

func Sum(a, b int) int {
	return a + b
}

func main() {
	cases := []struct {
		a, b int
		want int
	}{
		{1, 2, 3},
		{0, 0, 0},
		{-1, 1, 2},
	}
	passed := 0
	for _, tc := range cases {
		_ = tc // проверьте случай и увеличьте passed
	}
	fmt.Println(passed)
}
```

**Ожидаемый вывод:**

```text
2
```

**Подсказка.** Создайте срез структур с полями `a, b, want` и считайте совпадения.

**Решение:**

```go
package main

import "fmt"

func Sum(a, b int) int {
	return a + b
}

func main() {
	cases := []struct {
		a, b int
		want int
	}{
		{1, 2, 3},
		{0, 0, 0},
		{-1, 1, 2},
	}
	passed := 0
	for _, tc := range cases {
		if Sum(tc.a, tc.b) == tc.want {
			passed++
		}
	}
	fmt.Println(passed)
}
```

## Резюме

- Табличный тест перебирает срез структур с входами и ожиданиями.
- Имя случая помогает найти провал в отчёте.
- Включайте граничные значения и ошибочные сценарии.
