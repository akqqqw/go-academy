## Паника останавливает программу

`panic(v)` прерывает обычное выполнение, запускает отложенные `defer` и роняет
программу с трассировкой. Паника — для ситуаций, которые код не умеет
обрабатывать: неверный индекс, nil-указатель, нарушенный инвариант.

```go
package main

import "fmt"

func mustPositive(n int) int {
	if n <= 0 {
		panic("нужно положительное число")
	}
	return n
}

func main() {
	fmt.Println(mustPositive(3))
}
```

## recover внутри defer

`recover()` возвращает значение паники и останавливает её, но работает только
внутри отложенной функции:

```go
func safeDivide(a, b int) (result int, err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("деление: %v", r)
		}
	}()
	return a / b, nil
}
```

Именованный результат обязателен: `err` должен быть виден отложенной функции.

## Где это применяют

- Границы сервера: middleware ловит панику обработчика и возвращает 500 вместо
  падения процесса.
- Пакеты вроде `encoding/json` перехватывают панику глубоко внутри и превращают
  её в ошибку.
- Плагины и пользовательский код, который нельзя доверять.

Внутри бизнес-логики `recover` не заменяет обработку ошибок.

## Частые ошибки

- **recover вне defer.** Возвращает nil, паника продолжается.
- **Ожидание возобновления.** После recover функция не продолжается с места
  паники — она завершается.
- **Паника вместо ошибки.** Ожидаемые сбои (нет файла, битый JSON) — это `error`.
- **Глотание паники без логирования.** Диагностика теряется; логируйте стек.

## Практика

**Задание.** Напишите `safeDivide(a, b int) (int, error)`, которая ловит панику деления на ноль через `recover` и возвращает ошибку; вызовите её с `b = 0`.

**Стартовый код:**

```go
package main

import "fmt"

func safeDivide(a, b int) (result int, err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("ошибка: %v", r)
		}
	}()
	return a / b, nil
}

func main() {
	result, err := safeDivide(10, 0)
	if err != nil {
		fmt.Println(err)
		return
	}
	fmt.Println(result)
}
```

**Ожидаемый вывод:**

```text
ошибка: runtime error: integer divide by zero
```

**Подсказка.** Объявите именованные результаты и `defer` с `recover`, присваивая `err`.

**Решение:**

```go
package main

import "fmt"

func safeDivide(a, b int) (result int, err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("ошибка: %v", r)
		}
	}()
	return a / b, nil
}

func main() {
	if _, err := safeDivide(10, 0); err != nil {
		fmt.Println(err)
	}
}
```

## Резюме

- `panic` прерывает программу, запуская отложенные функции.
- `recover` работает только внутри `defer` и завершает функцию.
- Ожидаемые сбои возвращают ошибку; паника — для нарушенных инвариантов.
