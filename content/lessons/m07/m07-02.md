## Своя структура ошибки

Строки мало, когда вызывающему коду нужны детали. Тогда объявляют тип с методом
`Error()`:

```go
package main

import (
	"errors"
	"fmt"
)

type ValidationError struct {
	Field string
	Value string
}

func (e *ValidationError) Error() string {
	return fmt.Sprintf("поле %s: недопустимое значение %q", e.Field, e.Value)
}

func checkEmail(email string) error {
	if email == "" {
		return &ValidationError{Field: "email", Value: email}
	}
	return nil
}

func main() {
	err := checkEmail("")
	fmt.Println(err)

	var validation *ValidationError
	if errors.As(err, &validation) {
		fmt.Println("поле с ошибкой:", validation.Field)
	}
}
```

## Указатель или значение

Метод `Error()` можно объявить на значении или указателе. Указатель удобнее:
не копирует структуру и позволяет `errors.As` заполнить переменную. Но тогда и
возвращать нужно `&ValidationError{...}`.

## Сентинел против типа

- **Сентинел** — одна переменная: `var ErrNotFound = errors.New("не найдено")`.
  Сравнивают через `errors.Is`.
- **Тип** — когда нужны поля. Проверяют через `errors.As`.
- Не смешивайте: тип, который ещё и сравнивают с сентинелом, тяжело
  поддерживать.

## Частые ошибки

- **Метод на значении, а возвращается указатель.** `errors.As` с `*T` не найдёт
  `T`; следите за согласованностью.
- **Пустой текст ошибки.** `Error()` не должен возвращать `""` — логи станут
  бесполезными.
- **Чувствительные данные в тексте.** Пароли и токены в ошибки не попадают.
- **Ошибка без контекста.** «invalid» хуже, чем «поле email: пустое значение».

## Практика

**Задание.** Объявите тип `NotFoundError` с полем `ID` и методом `Error()`, верните его из функции `find` и проверьте через `errors.As`.

**Стартовый код:**

```go
package main

import (
	"errors"
	"fmt"
)

type NotFoundError struct {
	ID int
}

func (e *NotFoundError) Error() string {
	return fmt.Sprintf("запись %d не найдена", e.ID)
}

func find(id int) error {
	if id <= 0 {
		return nil // верните ошибку NotFoundError
	}
	return nil
}

func main() {
	err := find(0)
	var target *NotFoundError
	if errors.As(err, &target) {
		fmt.Println("id:", target.ID)
	}
}
```

**Ожидаемый вывод:**

```text
id: 0
```

**Подсказка.** Возвращайте `&NotFoundError{ID: id}` и проверяйте `var target *NotFoundError; errors.As(err, &target)`.

**Решение:**

```go
package main

import (
	"errors"
	"fmt"
)

type NotFoundError struct {
	ID int
}

func (e *NotFoundError) Error() string {
	return fmt.Sprintf("запись %d не найдена", e.ID)
}

func find(id int) error {
	if id <= 0 {
		return &NotFoundError{ID: id}
	}
	return nil
}

func main() {
	err := find(0)
	var target *NotFoundError
	if errors.As(err, &target) {
		fmt.Println("id:", target.ID)
	}
}
```

## Резюме

- Свой тип ошибки несёт данные и реализует `Error() string`.
- Указательный тип ошибки удобнее для `errors.As`.
- Сентинелы — для простых случаев, типы — когда нужны детали.

`errors.New` и сентинел-ошибки: как сравнивать их правильно.
