## Пакет — это единица компиляции

В Go код группируется в пакеты. Все файлы одного каталога должны объявлять одно
и то же имя пакета:

```text
mathutil/
├── add.go      → package mathutil
└── mul.go      → package mathutil
```

Внутри пакета имена видны друг другу напрямую, без импорта. За пределами пакета
доступны только **экспортированные** имена — те, что начинаются с заглавной
буквы.

```go
package mathutil

// Sum экспортирована: видна другим пакетам.
func Sum(a, b int) int { return a + b }

// helper не экспортирована: доступна только внутри mathutil.
func helper() string { return "internal" }
```

## Особый статус `package main`

Компилятор различает два вида пакетов:

1. **Библиотечный пакет** — например, `strings`, `math`, `mathutil`. Его
   компилируют в архив, который импортируют другие пакеты. Собрать из него
   исполняемый файл нельзя.
2. **Исполняемый пакет** — пакет с особым именем `main`. Из него `go build`
   создаёт бинарник, а при запуске вызывается функция `main()`.

Отсюда правило: **одна программа — ровно один пакет `main` с функцией `main`.**
Если назвать пакет `app`, `go build` скажет:

```text
package command-line-arguments is not a main package
```

Важно: `package main` — это имя, а не путь. Каталог может называться как угодно.

## Имя пакета и путь импорта

Импортируют **путь**, а обращаются к **имени пакета**:

```go
import "strings"

func main() {
	fmt.Println(strings.ToUpper("go"))
}
```

Здесь путь `"strings"` совпадает с именем. Но так бывает не всегда: путь
`"github.com/google/uuid"` даёт пакет с именем `uuid`. Имя определяется строкой
`package ...`, а не последним элементом пути.

Можно переименовать импорт, если имя неудобно или конфликтует:

```go
import (
	str "strings"
	"example.com/hello/internal/storage"
)
```

Тогда вызывают `str.ToUpper(...)`. Пустой импорт `_ "pkg"` используют, когда пакет
нужен только ради побочного эффекта (например, регистрации драйвера).

## Собственный пакет и main

Раскладка из двух пакетов в одном модуле:

```text
greeter/
├── go.mod                     module example.com/greeter
├── main.go                    package main
└── greeting/
    └── greeting.go            package greeting
```

`greeting/greeting.go`:

```go
package greeting

import "fmt"

// Hello возвращает приветствие для имени.
func Hello(name string) string {
	return fmt.Sprintf("Привет, %s!", name)
}
```

`main.go`:

```go
package main

import (
	"fmt"

	"example.com/greeter/greeting"
)

func main() {
	message := greeting.Hello("Мир")
	fmt.Println(message)
}
```

Вывод: `Привет, Мир!`

Обратите внимание: функция называется с заглавной буквы (`Hello`), иначе импорт
не увидит её.

## Несколько пакетов main

В большом проекте часто есть несколько программ: сервер, CLI, мигратор. Каждая
живёт в своём каталоге `cmd/...`:

```text
cmd/
├── server/main.go     package main
└── migrate/main.go    package main
```

Это **разные** пакеты, потому что это разные каталоги. Конфликта нет: команда
`go build ./cmd/server` соберёт сервер, `go build ./cmd/migrate` — мигратор.
Файлы двух `main` никогда не компилируются вместе.

## Частые ошибки

- **`package main` в нескольких файлах одного каталога с разными функциями
  `main`.** В одном пакете может быть только одна функция `main`.
- **Импорт самого себя.** Пакет не может импортировать собственный путь —
  получится цикл компиляции.
- **Циклические импорты.** Если `a` импортирует `b`, то `b` не может
  импортировать `a`. Решение — вынести общий код в третий пакет.
- **Имя пакета с дефисом.** `package my-app` — синтаксическая ошибка: имена
  пакетов пишут строчными буквами без `-` и `_`.
- **Забыть заглавную букву.** `greeting.hello(...)` не скомпилируется, если
  функция объявлена как `hello`.
- **Считать, что `go build` соберёт библиотечный пакет.** Для пакета без `main`
  команда проверит компиляцию, но файла не создаст.

## Практика

**Задание.** Реализуйте функцию `hello(name string) string`, которая возвращает
строку `"Привет, <name>!"`, и напечатайте результат для имени «Go».

В настоящем проекте такая функция живёт в отдельном пакете `greeting` (см.
теорию выше). Редактор на странице урока работает с одним файлом, поэтому здесь
мы объявляем её в `package main` с тем же именем и сигнатурой.

**Стартовый код:**

```go
package main

import "fmt"

func hello(name string) string {
	return "" // верните приветствие
}

func main() {
	fmt.Println(hello("Go"))
}
```

**Ожидаемый вывод:**

```text
Привет, Go!
```

**Подсказка.** Используйте `fmt.Sprintf("Привет, %s!", name)`.

**Решение:**

```go
package main

import "fmt"

func hello(name string) string {
	return fmt.Sprintf("Привет, %s!", name)
}

func main() {
	fmt.Println(hello("Go"))
}
```

В проекте из нескольких файлов эта же функция переезжает в каталог `greeting`:

```go
// greeting/greeting.go
package greeting

import "fmt"

func Hello(name string) string {
	return fmt.Sprintf("Привет, %s!", name)
}
```

## Резюме

- Пакет объединяет файлы одного каталога; импортируют путь, вызывают по имени
  пакета.
- `package main` и функция `main()` делают пакет исполняемым.
- Экспортируется только то, что начинается с заглавной буквы.
- Несколько программ в одном модуле живут в отдельных каталогах `cmd/`.

Теперь посмотрим на функцию `main()` внимательнее: аргументы, код возврата и
порядок запуска.
