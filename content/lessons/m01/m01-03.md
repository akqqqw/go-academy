## Модуль и пакет

В Go есть две единицы организации кода, и их легко перепутать.

- **Пакет** — каталог с `.go` файлами, которые начинаются с одного
  `package <имя>`. Внутри пакета имена видны друг другу напрямую.
- **Модуль** — набор пакетов, у которого есть файл `go.mod` с путём модуля и
  версией языка. Модуль задаёт, как импортировать собственные пакеты и какие
  внешние зависимости нужны.

Один модуль может содержать десятки пакетов. Один пакет — только один каталог.

## Создаём модуль

```bash
mkdir hello
cd hello
go mod init example.com/hello
```

Появится `go.mod`:

```text
module example.com/hello

go 1.23
```

Первая строка — **путь модуля**. Для учебных проектов подойдёт любое имя
(`example.com/hello`, `github.com/user/hello`). Если вы планируете публиковать
код, путь должен совпадать с адресом репозитория: по нему Go будет скачивать
модуль.

`go 1.23` фиксирует минимальную версию языка. Это не «версия вашего Go», а
требование к компилятору.

## Простой проект: один файл

Для небольших программ достаточно одного `main.go` в корне модуля:

```text
hello/
├── go.mod
└── main.go
```

`main.go`:

```go
package main

import "fmt"

func main() {
	fmt.Println("Проект создан")
}
```

Запуск из корня модуля:

```bash
go run .
```

Точка означает «собери пакет в текущем каталоге». Можно указать файл явно:
`go run main.go`, но при нескольких файлах это неудобно — используйте `go run .`.

## Проект побольше: cmd и internal

Когда файлов становится много, помогает раскладка, принятая в сообществе:

```text
myapp/
├── go.mod
├── cmd/
│   └── myapp/
│       └── main.go        ← package main, только запуск
├── internal/
│   ├── storage/
│   │   └── storage.go     ← package storage, работа с данными
│   └── api/
│       └── api.go         ← package api, HTTP-слой
└── pkg/
    └── client/
        └── client.go      ← package client, публичный код
```

- `cmd/имя` — точки входа. Каждый подкаталог даёт отдельный бинарник с чистым
  `main`, который только собирает зависимости и запускает приложение.
- `internal` — код, который нельзя импортировать из других модулей. Компилятор
  запретит такой импорт, и это защищает внутренние детали.
- `pkg` — необязательный каталог для кода, которым пользуются снаружи.

Внутри `internal/storage/storage.go` будет:

```go
package storage

// Open готовит хранилище (пример сигнатуры).
func Open(path string) error {
	return nil
}
```

А в `cmd/myapp/main.go` появится импорт:

```text
import "example.com/hello/internal/storage"
```

Импортируется **путь модуля + путь каталога**, а обращаются к функциям по имени
пакета: `storage.Open(...)`.

## Как компилятор находит пакеты

1. Читает `go.mod` в текущем или родительском каталоге.
2. Для импорта `example.com/hello/internal/storage` ищет пакет внутри модуля по
   относительному пути.
3. Для внешних путей (`github.com/...`) скачивает модуль в кеш.

Поэтому запускать команды `go run`, `go build`, `go test` нужно **внутри
модуля**, иначе Go не поймёт, к какому проекту относится код.

## Сборка

```bash
go build -o bin/hello ./cmd/myapp
```

Флаг `-o` задаёт имя и место бинарника. Без него файл появится в текущем
каталоге и получит имя каталога пакета.

Можно собрать всё сразу:

```bash
go build ./...
```

Три точки после слэша — «все пакеты модуля». Это удобно перед коммитом: так вы
увидите ошибки компиляции во всех пакетах, а не только в текущем.

## Частые ошибки

- **`go: cannot find main module`.** Команда запущена вне модуля — нет `go.mod`.
  Решение: `cd` в корень проекта или `go mod init`.
- **Разные имена пакетов в одном каталоге.** Если в папке лежат файлы с
  `package main` и `package utils`, компилятор выдаст ошибку. Все файлы каталога
  — один пакет.
- **`package main` внутри `internal`.** Работать будет, но это лишает смысла
  раскладку: код точки входа принято держать в `cmd`.
- **Путь модуля и импорт не совпадают.** Импорт `example.com/hello/internal/x`
  работает только если `module example.com/hello`.
- **Запуск `go run main.go` при нескольких файлах.** Так компилируется только
  один файл. Используйте `go run .`.

## Практика

**Задание.** Создайте модуль `example.com/practice`, в нём файл `main.go`,
который печатает имя модуля и приветствие. Запустите через `go run .`.

**Стартовый код:**

```go
package main

import "fmt"

func main() {
	const moduleName = "example.com/practice"
	fmt.Println("Модуль:", moduleName)
	fmt.Println("Готов к работе")
}
```

**Ожидаемый вывод:**

```text
Модуль: example.com/practice
Готов к работе
```

**Подсказка.** Сначала выполните `go mod init example.com/practice`, затем
создайте файл и запустите `go run .`. Если запустить без `go.mod`, Go сообщит об
отсутствии модуля.

Главное — выполнить инициализацию модуля до запуска: без `go.mod` команда
`go run .` не найдёт модуль.

**Решение:**

```go
package main

import "fmt"

func main() {
	const moduleName = "example.com/practice"
	fmt.Println("Модуль:", moduleName)
	fmt.Println("Готов к работе")
}
```

## Резюме

- Пакет — каталог с Go-файлами, модуль — набор пакетов с `go.mod`.
- `go mod init <путь>` создаёт модуль; запускать команды нужно внутри него.
- Для небольшого проекта хватит `main.go`, для растущего — `cmd/`, `internal/`
  и `pkg/`.
- `go run .` собирает и запускает пакет в текущем каталоге, `go build ./...`
  проверяет весь модуль.

Теперь напишем и разберём первую настоящую программу.
