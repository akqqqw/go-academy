## Стек и куча

- **Стек** — быстрый, освобождается автоматически при выходе из функции.
- **Куча** — общая, очищается сборщиком мусора.

Go решает, куда положить значение, через escape analysis. Если указатель
«убегает» из функции, значение уйдёт в кучу:

```go
func newCounter() *int {
	value := 0
	return &value // value уйдёт в кучу
}
```

## Посмотреть решение компилятора

```bash
go build -gcflags='-m' ./...
```

Сообщения вида `moved to heap: value` показывают причины. Это диагностика, а не
рецепт: вручную управлять размещением нельзя.

## Как уменьшать аллокации

- Задавайте ёмкость среза заранее: `make([]T, 0, n)`.
- Избегайте конкатенации строк в цикле — `strings.Builder`.
- Переиспользуйте буферы (`sync.Pool`) в горячих путях.
- Передавайте структуры указателем, если они большие, и значением, если
  маленькие: копия маленькой структуры дешевле указателя и лучше для кеша.
- Не оптимизируйте вслепую: измеряйте `allocs/op` в бенчмарке.

## Профиль памяти

```bash
go test -bench=. -memprofile=mem.out
go tool pprof -top mem.out
```

`inuse_space` — что занято сейчас, `alloc_space` — сколько всего выделено.

## Частые ошибки

- **Возвращать указатель на локальную переменную ради «экономии».** Это лишняя
  аллокация, а не оптимизация.
- **Пул объектов без нужды.** `sync.Pool` усложняет код и не гарантирует
  переиспользование.
- **`append` без ёмкости в цикле на миллион элементов.** Много копирований.
- **Оптимизация без профиля.** Время уходит не туда.

## Практика

**Задание.** Сравните число аллокаций при добавлении 1000 элементов в срез без ёмкости и с `make([]int, 0, 1000)`, напечатав, сколько раз менялась ёмкость во втором случае.

**Стартовый код:**

```go
package main

import "fmt"

func main() {
	withoutCap := make([]int, 0)
	grows := 0
	prev := cap(withoutCap)
	for i := 0; i < 1000; i++ {
		withoutCap = append(withoutCap, i)
		if cap(withoutCap) != prev {
			grows++
			prev = cap(withoutCap)
		}
	}

	withCap := make([]int, 0, 1000)
	prev = cap(withCap)
	growsWithCap := 0
	for i := 0; i < 1000; i++ {
		withCap = append(withCap, i)
		if cap(withCap) != prev {
			growsWithCap++
			prev = cap(withCap)
		}
	}

	fmt.Println(grows, growsWithCap)
}
```

**Ожидаемый вывод:**

```text
true
```

**Подсказка.** Во втором случае цикл `append` не должен менять `cap`: посчитайте изменения `cap` до и после.

**Решение:**

```go
package main

import "fmt"

func main() {
	withCap := make([]int, 0, 1000)
	prev := cap(withCap)
	grows := 0
	for i := 0; i < 1000; i++ {
		withCap = append(withCap, i)
		if cap(withCap) != prev {
			grows++
			prev = cap(withCap)
		}
	}
	fmt.Println(grows == 0)
}
```

## Резюме

- Go сам выбирает стек или кучу через escape analysis.
- `-gcflags='-m'` показывает решения компилятора.
- Меньше аллокаций — заранее известная ёмкость, Builder и буферы.
