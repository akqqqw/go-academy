## Ограничение параллелизма

Семафор на канале — простой способ не превысить лимит:

```go
func fetchAll(urls []string) []string {
	sem := make(chan struct{}, 4)
	results := make([]string, len(urls))

	var wg sync.WaitGroup
	for i, url := range urls {
		wg.Add(1)
		go func(i int, url string) {
			defer wg.Done()
			sem <- struct{}{}
			defer func() { <-sem }()
			results[i] = fetch(url)
		}(i, url)
	}
	wg.Wait()
	return results
}
```

Запись в `results[i]` безопасна: у каждой горутины свой индекс.

## Ошибки из горутин

Первую ошибку передают через канал или `context.WithCancel`:

```go
func run(ctx context.Context, tasks []func(context.Context) error) error {
	ctx, cancel := context.WithCancel(ctx)
	defer cancel()

	errs := make(chan error, len(tasks))
	var wg sync.WaitGroup
	for _, task := range tasks {
		wg.Add(1)
		go func(task func(context.Context) error) {
			defer wg.Done()
			if err := task(ctx); err != nil {
				errs <- err
				cancel()
			}
		}(task)
	}
	wg.Wait()
	close(errs)
	return <-errs
}
```

В реальном коде удобен `golang.org/x/sync/errgroup`, но принцип тот же.

## Устойчивость

- Ограничивайте параллелизм по внешнему ресурсу (пул БД, лимиты API).
- Ставьте таймауты на каждую операцию.
- Ретраи — только для идемпотентных операций, с backoff.
- Не собирайте неограниченное число результатов в память.

## Частые ошибки

- **Горутина на каждую задачу без лимита.** Исчерпание ресурсов.
- **`wg.Wait()` до чтения из небуферизованного канала ошибок.** Взаимная
  блокировка.
- **Игнорирование отмены.** Задачи продолжают работу после ошибки.
- **Общий срез без индексов.** Гонка данных.

## Практика

**Задание.** Ограничьте параллелизм четырьмя горутинами: обработайте 10 чисел, сложите результаты и напечатайте сумму.

**Стартовый код:**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	const workers = 4
	sem := make(chan struct{}, workers)
	results := make([]int, 10)

	var wg sync.WaitGroup
	for i := range results {
		wg.Add(1)
		go func(index int) {
			defer wg.Done()
			sem <- struct{}{}
			defer func() { <-sem }()
			results[index] = (index + 1) * 2 // удвойте число
		}(i)
	}
	wg.Wait()

	total := 0
	for _, value := range results {
		total += value
	}
	fmt.Println(total)
}
```

**Ожидаемый вывод:**

```text
110
```

**Подсказка.** Используйте буферизованный канал-семафор на 4 и срез результатов по индексам.

**Решение:**

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	const workers = 4
	sem := make(chan struct{}, workers)
	results := make([]int, 10)

	var wg sync.WaitGroup
	for i := range results {
		wg.Add(1)
		go func(index int) {
			defer wg.Done()
			sem <- struct{}{}
			defer func() { <-sem }()
			results[index] = (index + 1) * 2
		}(i)
	}
	wg.Wait()

	total := 0
	for _, value := range results {
		total += value
	}
	fmt.Println(total)
}
```
