## Снятие профиля

```bash
go test -bench=. -cpuprofile=cpu.out ./pkg
go tool pprof -top cpu.out
go tool pprof -http=:8081 cpu.out
```

В `top` смотрите столбцы `flat` (время в самой функции) и `cum` (включая
вызовы). `-http` открывает граф и флеймграф.

## В сервисе

```go
import _ "net/http/pprof"

go func() {
	log.Println(http.ListenAndServe("127.0.0.1:6060", nil))
}()
```

Затем:

```bash
go tool pprof http://127.0.0.1:6060/debug/pprof/profile?seconds=30
go tool pprof http://127.0.0.1:6060/debug/pprof/heap
```

Порт профилирования держите только на localhost: он раскрывает внутренности
приложения.

## Виды профилей

| Профиль | Что показывает |
| --- | --- |
| `profile` | CPU |
| `heap` | распределение памяти |
| `goroutine` | стеки всех горутин (утечки) |
| `block` | ожидание на блокировках |
| `mutex` | конкуренция за мьютексы |
| `trace` | хронология выполнения |

## Методика

1. Сформулируйте гипотезу: где медленно?
2. Снимите профиль под реалистичной нагрузкой.
3. Оптимизируйте одно место.
4. Повторите замер и сравните.

## Частые ошибки

- **Оптимизация без профиля.** Ускоряете то, что не было узким местом.
- **Профиль на пустом сервисе.** Нужна нагрузка.
- **Профилирование в проде без защиты.** Порт 6060 нельзя открывать наружу.
- **Игнорирование `block`/`mutex`.** Медленность бывает из-за ожиданий.

## Практика

**Задание.** Соберите простой замер: посчитайте сумму 1..1 000 000 двумя способами (цикл и формула) и напечатайте результат формулы.

**Стартовый код:**

```go
package main

import "fmt"

func main() {
	const n = 1_000_000
	sum := 0
	for i := 1; i <= n; i++ {
		sum += i
	}
	_ = sum
	// посчитайте сумму формулой и напечатайте
	fmt.Println(0)
}
```

**Ожидаемый вывод:**

```text
500000500000
```

**Подсказка.** Формула суммы: `n * (n + 1) / 2`.

**Решение:**

```go
package main

import "fmt"

func main() {
	const n = 1_000_000
	sum := 0
	for i := 1; i <= n; i++ {
		sum += i
	}
	formula := n * (n + 1) / 2
	_ = sum
	fmt.Println(formula)
}
```

## Резюме

- pprof даёт профили CPU, памяти, горутин, блокировок и трейс.
- В сервисе профиль доступен через `net/http/pprof` на localhost.
- Без реалистичной нагрузки профиль бесполезен.

Оптимизация: бенчмарки, бюджет и читаемость.
