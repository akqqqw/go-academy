## Сначала измерение

Правило: сначала бенчмарк или профиль, потом правка. «Оптимизация наугад» часто
делает код сложнее и медленнее.

```go
func BenchmarkParse(b *testing.B) {
	data := loadFixture()
	b.ResetTimer()
	for i := 0; i < b.N; i++ {
		if _, err := parse(data); err != nil {
			b.Fatal(err)
		}
	}
}
```

## Типовые ускорения

| Проблема | Решение |
| --- | --- |
| Конкатенация в цикле | `strings.Builder` |
| Много аллокаций срезов | заранее `make([]T, 0, n)` |
| Повторный парсинг | кеш или предвычисление |
| Лишние копии структур | указатели для больших значений |
| Частые обращения к БД | пакетные запросы, индексы |
| Ожидание по одному | конкурентные запросы с лимитом |

## Конкурентность не всегда быстрее

Горутины добавляют накладные расходы и синхронизацию. Для маленьких задач
последовательный код быстрее. Параллелизм помогает, когда есть I/O или тяжёлые
вычисления на несколько ядер.

## Бюджет

Определите цель: например, «p99 ответа < 100 мс». Если цель достигнута,
остановитесь. Преждевременная оптимизация повышает риск багов.

## Частые ошибки

- **Микрооптимизации без профиля.** Трата времени.
- **Кеш без инвалидации.** Устаревшие данные хуже медленных.
- **Жертвовать читаемостью ради 5%.** Поддержка дороже.
- **Сравнение бенчмарков в разных условиях.** Некорректные выводы.

## Практика

**Задание.** Ускорьте подсчёт частоты слов: замените конкатенацию ключа на `strings.Builder` и напечатайте частоту слова `go`.

**Стартовый код:**

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	text := "go is fast go is simple go"
	counts := make(map[string]int)
	for _, word := range strings.Fields(text) {
		_ = word // увеличьте счётчик слова
	}
	fmt.Println(counts["go"])
}
```

**Ожидаемый вывод:**

```text
3
```

**Подсказка.** Соберите `map[string]int` по словам `strings.Fields` и напечатайте `counts["go"]`.

**Решение:**

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	text := "go is fast go is simple go"
	counts := make(map[string]int)
	for _, word := range strings.Fields(text) {
		counts[word]++
	}
	fmt.Println(counts["go"])
}
```

## Резюме

- Оптимизируйте только после измерения и с понятной целью.
- Типовые выигрыши: Builder, ёмкость, кеш, пакетные запросы.
- Читаемость и корректность важнее нескольких процентов.

Архитектура приложений: слои, зависимости и тестируемость.
