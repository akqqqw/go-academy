## Слои

```text
HTTP-обработчик  →  сервис/хранилище  →  БД
```

Обработчик занимается только разбором запроса и ответом, хранилище — SQL.
Интерфейс хранилища позволяет подменить его в тестах:

```go
type NoteStore interface {
	List(ctx context.Context) ([]Note, error)
	Get(ctx context.Context, id int) (Note, error)
	Create(ctx context.Context, note Note) (int, error)
	Delete(ctx context.Context, id int) error
}
```

## Операции

| Операция | HTTP | Ответ |
| --- | --- | --- |
| List | `GET /api/notes` | 200, массив |
| Get | `GET /api/notes/{id}` | 200 или 404 |
| Create | `POST /api/notes` | 201, `Location` |
| Update | `PATCH /api/notes/{id}` | 200 или 404/422 |
| Delete | `DELETE /api/notes/{id}` | 204 или 404 |

## Обработчик

```go
func (s *Server) getNote(w http.ResponseWriter, r *http.Request) {
	id, err := strconv.Atoi(r.PathValue("id"))
	if err != nil {
		writeError(w, http.StatusBadRequest, "invalid_id", "id должен быть числом")
		return
	}
	note, err := s.store.Get(r.Context(), id)
	if errors.Is(err, ErrNotFound) {
		writeError(w, http.StatusNotFound, "note_not_found", "заметка не найдена")
		return
	}
	if err != nil {
		s.log.Error("получить заметку", "err", err)
		writeError(w, http.StatusInternalServerError, "internal", "внутренняя ошибка")
		return
	}
	writeJSON(w, http.StatusOK, note)
}
```

## Тестируемость

С `NoteStore` тест обработчика не требует SQLite: достаточно реализации в памяти
с нужным поведением. Это и есть смысл интерфейса на стороне потребителя.

## Частые ошибки

- **SQL прямо в обработчике.** Слой размывается, тесты требуют БД.
- **Утечка текста ошибки БД в ответ.** Пользователю — общий текст, детали — в лог.
- **404 на любую ошибку.** 500 и 404 — разные ситуации.
- **Обновление без проверки результата.** `RowsAffected()` покажет, был ли id.

## Практика

**Задание.** Реализуйте хранилище в памяти: `Create` добавляет заметку и возвращает id, `Count` — число заметок; создайте две и напечатайте id второй и количество.

**Стартовый код:**

```go
package main

import "fmt"

type Note struct {
	Title string
}

type Store struct {
	notes []Note
}

func (s *Store) Create(title string) int {
	return 0 // добавьте заметку и верните её id
}

func (s *Store) Count() int {
	return len(s.notes)
}

func main() {
	store := &Store{}
	store.Create("первая")
	id := store.Create("вторая")
	fmt.Println(id, store.Count())
}
```

**Ожидаемый вывод:**

```text
2 2
```

**Подсказка.** Держите срез в структуре `Store`, `Create` возвращает `len(s.notes)`.

**Решение:**

```go
package main

import "fmt"

type Note struct {
	Title string
}

type Store struct {
	notes []Note
}

func (s *Store) Create(title string) int {
	s.notes = append(s.notes, Note{Title: title})
	return len(s.notes)
}

func (s *Store) Count() int {
	return len(s.notes)
}

func main() {
	store := &Store{}
	store.Create("первая")
	id := store.Create("вторая")
	fmt.Println(id, store.Count())
}
```

## Резюме

- Хранилище и HTTP разделены интерфейсом — так проще тестировать.
- Каждая CRUD-операция имеет свой код ответа.
- Подробности ошибок идут в лог, клиенту — общий текст.
