## Запрос и ответ

HTTP — текстовая модель «запрос → ответ». Клиент присылает метод, путь, заголовки
и тело; сервер отвечает кодом состояния, заголовками и телом.

```text
GET /api/lessons/m01-01 HTTP/1.1
Host: localhost:8080
Accept: application/json

HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 42

{"id":"m01-01","status":"completed"}
```

## Методы

| Метод | Смысл | Идемпотентный |
| --- | --- | --- |
| `GET` | получить | да |
| `POST` | создать / действие | нет |
| `PUT` | заменить целиком | да |
| `PATCH` | изменить частично | нет |
| `DELETE` | удалить | да |

Идемпотентность значит, что повтор запроса не меняет результат. REST-клиенты и
прокси на это полагаются.

## Коды состояния

- `2xx` — успех: `200 OK`, `201 Created`, `204 No Content`.
- `3xx` — перенаправление: `301`, `304`.
- `4xx` — ошибка клиента: `400` (неверные данные), `401`, `403`, `404`, `405`,
  `409`, `422`.
- `5xx` — ошибка сервера: `500`, `503`.

Код — часть контракта: фронтенд не должен угадывать по тексту, что произошло.

## Заголовки

`Content-Type` описывает тело (`application/json; charset=utf-8`), `Accept` —
что клиент готов принять, `Cache-Control` — кеширование, `Authorization` —
аутентификацию.

## Частые ошибки

- **200 с `{"error": ...}`.** Клиент не отличит успех от ошибки; используйте 4xx/5xx.
- **`404` вместо `405`.** Неверный метод — это 405 с заголовком `Allow`.
- **Тело в GET.** Не предусмотрено спецификацией и плохо кешируется.
- **Кеширование 401.** Укажите `Cache-Control: no-store`.

## Практика

**Задание.** Опишите обработчик, который возвращает `201` и JSON `{"status":"created"}` для POST и `405` для остальных методов; вызовите его через `httptest` и напечатайте коды.

**Стартовый код:**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func handler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		w.WriteHeader(http.StatusMethodNotAllowed)
		return
	}
	w.WriteHeader(http.StatusOK) // верните 201 и JSON
}

func main() {
	for _, method := range []string{http.MethodPost, http.MethodGet} {
		recorder := httptest.NewRecorder()
		handler(recorder, httptest.NewRequest(method, "/items", nil))
		fmt.Println(recorder.Code)
	}
}
```

**Ожидаемый вывод:**

```text
201
405
```

**Подсказка.** Проверьте `r.Method != http.MethodPost` и используйте `httptest.NewRecorder()`.

**Решение:**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func handler(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		w.WriteHeader(http.StatusMethodNotAllowed)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	fmt.Fprint(w, `{"status":"created"}`)
}

func main() {
	for _, method := range []string{http.MethodPost, http.MethodGet} {
		recorder := httptest.NewRecorder()
		handler(recorder, httptest.NewRequest(method, "/items", nil))
		fmt.Println(recorder.Code)
	}
}
```

## Резюме

- HTTP-обмен: метод, путь, заголовки, тело и код состояния.
- Методы различаются идемпотентностью, коды — ответственностью клиента или сервера.
- Код состояния должен соответствовать результату, а не только тексту.

`net/http` — сервер, маршрутизация и обработчики.
