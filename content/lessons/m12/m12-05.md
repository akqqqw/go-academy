## Декоратор для обработчика

Middleware принимает `http.Handler` и возвращает `http.Handler`:

```go
func logging(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		next.ServeHTTP(w, r)
		log.Printf("%s %s %s", r.Method, r.URL.Path, time.Since(start))
	})
}
```

Обёртка `statusRecorder` позволяет узнать код ответа, перехватив `WriteHeader`.

## Цепочка

```go
handler := logging(recoverer(mux))
http.ListenAndServe(":8080", handler)
```

Порядок важен: внешний middleware видит запрос первым. Логирование обычно
снаружи, восстановление после паники — тоже.

## Восстановление

```go
func recoverer(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				log.Printf("паника: %v", rec)
				http.Error(w, "внутренняя ошибка", http.StatusInternalServerError)
			}
		}()
		next.ServeHTTP(w, r)
	})
}
```

## Контекст и заголовки

Middleware может добавить `X-Request-ID`, `Cache-Control`, проверить токен и
положить данные в `r.Context()`:

```go
ctx := context.WithValue(r.Context(), key, value)
next.ServeHTTP(w, r.WithContext(ctx))
```

## Частые ошибки

- **Забыть `next.ServeHTTP`.** Запрос «повиснет» без ответа.
- **Паника в middleware вне recover.** Роняет процесс.
- **Хранить `context` в структуре.** Передавайте через `r.Context()`.
- **Много «универсальных» middleware.** Каждая должна делать одно.

## Практика

**Задание.** Напишите middleware, добавляющее заголовок `X-App: go-academy`, и проверьте его через `httptest`, напечатав значение заголовка.

**Стартовый код:**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func withHeader(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// добавьте заголовок X-App
		next.ServeHTTP(w, r)
	})
}

func main() {
	handler := withHeader(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "ok")
	}))

	recorder := httptest.NewRecorder()
	handler.ServeHTTP(recorder, httptest.NewRequest(http.MethodGet, "/", nil))
	fmt.Println(recorder.Header().Get("X-App"))
}
```

**Ожидаемый вывод:**

```text
go-academy
```

**Подсказка.** Middleware вызывает `next.ServeHTTP` после `w.Header().Set(...)`; заголовок читайте из `recorder.Header().Get(...)`.

**Решение:**

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func withHeader(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("X-App", "go-academy")
		next.ServeHTTP(w, r)
	})
}

func main() {
	handler := withHeader(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "ok")
	}))

	recorder := httptest.NewRecorder()
	handler.ServeHTTP(recorder, httptest.NewRequest(http.MethodGet, "/", nil))
	fmt.Println(recorder.Header().Get("X-App"))
}
```

## Резюме

- Middleware — функция `func(http.Handler) http.Handler`.
- Порядок обёрток задаёт порядок выполнения, восстанавливайте паники на границе.
- Данные запроса передаются через `r.Context()`, а не через глобальные переменные.
