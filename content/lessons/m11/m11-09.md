## Схема

Пул ограничивает параллелизм: задачи идут в канал, N воркеров их разбирают,
результаты собираются в другом канале.

```go
package main

import (
	"fmt"
	"sync"
)

func worker(id int, jobs <-chan int, results chan<- int) {
	for job := range jobs {
		results <- job * job
	}
}

func main() {
	jobs := make(chan int, 5)
	results := make(chan int, 5)

	var wg sync.WaitGroup
	for i := 1; i <= 3; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			worker(id, jobs, results)
		}(i)
	}

	for i := 1; i <= 5; i++ {
		jobs <- i
	}
	close(jobs)

	go func() {
		wg.Wait()
		close(results)
	}()

	total := 0
	for value := range results {
		total += value
	}
	fmt.Println(total)
}
```

## Ключевые моменты

- `close(jobs)` после отправки — воркеры завершат `range` и выйдут.
- `results` закрывается **после** `wg.Wait()`, иначе паника при записи в закрытый
  канал.
- Буфер результатов снижает блокировки, но не обязателен.
- Число воркеров обычно около `runtime.NumCPU()` или ограничено внешним
  ресурсом (БД, сеть).

## Зачем ограничивать

Запуск горутины на каждую задачу может исчерпать память, соединения или лимиты
API. Пул даёт контролируемую нагрузку и предсказуемое потребление ресурсов.

## Частые ошибки

- **Закрыть `jobs` несколько раз.** Паника.
- **Закрыть `results` до завершения воркеров.** `send on closed channel`.
- **Забыть `wg.Wait`.** Программа завершится раньше.
- **Возвращать результаты через общую map без мьютекса.** Гонка данных.

## Практика

**Задание.** Соберите пул из трёх воркеров, обработайте числа 1..6 (квадраты) и напечатайте сумму результатов.

**Стартовый код:**

```go
package main

import (
	"fmt"
	"sync"
)

func worker(jobs <-chan int, results chan<- int) {
	for job := range jobs {
		results <- job * job
	}
}

func main() {
	jobs := make(chan int, 6)
	results := make(chan int, 6)

	var wg sync.WaitGroup
	for i := 0; i < 3; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			worker(jobs, results)
		}()
	}

	// отправьте задачи 1..6 и закройте jobs
	for i := 1; i <= 6; i++ {
		_ = i
	}

	go func() {
		wg.Wait()
		close(results)
	}()

	total := 0
	for value := range results {
		total += value
	}
	fmt.Println(total)
}
```

**Ожидаемый вывод:**

```text
91
```

**Подсказка.** Отправьте задачи в `jobs`, закройте его, дождитесь воркеров и прочитайте `results` до закрытия.

**Решение:**

```go
package main

import (
	"fmt"
	"sync"
)

func worker(jobs <-chan int, results chan<- int) {
	for job := range jobs {
		results <- job * job
	}
}

func main() {
	jobs := make(chan int, 6)
	results := make(chan int, 6)

	var wg sync.WaitGroup
	for i := 0; i < 3; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			worker(jobs, results)
		}()
	}

	for i := 1; i <= 6; i++ {
		jobs <- i
	}
	close(jobs)

	go func() {
		wg.Wait()
		close(results)
	}()

	total := 0
	for value := range results {
		total += value
	}
	fmt.Println(total)
}
```

## Резюме

- Пул воркеров ограничивает параллелизм и защищает ресурсы.
- `jobs` закрывает отправитель, `results` — после `wg.Wait()`.
- Результаты собирают через канал, а не через общую map без блокировки.
