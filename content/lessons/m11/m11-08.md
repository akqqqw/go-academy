## Зачем контекст

`context.Context` переносит сигнал отмены, дедлайн и небольшие значения через
цепочку вызовов. В сетевом и конкурентном коде он почти обязателен.

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func work(ctx context.Context) error {
	select {
	case <-time.After(50 * time.Millisecond):
		return nil
	case <-ctx.Done():
		return ctx.Err()
	}
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 20*time.Millisecond)
	defer cancel()

	if err := work(ctx); err != nil {
		fmt.Println("отменено:", err)
		return
	}
	fmt.Println("готово")
}
```

`ctx.Err()` вернёт `context.DeadlineExceeded` или `context.Canceled`.

## Правила

- Контекст — **первый** параметр: `func Do(ctx context.Context, ...) error`.
- Не храните контекст в структуре, передавайте явно.
- `defer cancel()` обязателен, иначе таймер и ресурсы останутся.
- `context.Background()` — корень для `main` и тестов;
  `context.TODO()` — заглушка во время рефакторинга.
- Не передавайте в контекст бизнес-данные: только request-scoped значения
  (например, идентификатор запроса).

## Отмена в цепочке

Дочерний контекст `context.WithCancel(parent)` отменяется при отмене родителя.
Функции, поддерживающие контекст (`http.NewRequestWithContext`,
`db.QueryContext`), прерываются автоматически.

## Частые ошибки

- **Забыть `cancel`.** Утечка таймера и горутины.
- **Игнорировать `ctx.Done()`.** Операция продолжается после отмены.
- **Передавать `nil`.** Используйте `context.Background()`.
- **Проверять `ctx.Err()` вместо `select`.** В блокирующих операциях нужен
  `select` или API с поддержкой контекста.

## Практика

**Задание.** Создайте контекст с таймаутом 10 мс, запустите работу длиной 100 мс и напечатайте `deadline`, если контекст истёк.

**Стартовый код:**

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Millisecond)
	defer cancel()

	select {
	case <-time.After(100 * time.Millisecond):
		fmt.Println("done")
	case <-ctx.Done():
		fmt.Println("canceled")
	}
}
```

**Ожидаемый вывод:**

```text
deadline
```

**Подсказка.** `context.WithTimeout` + `select` с `<-ctx.Done()`; проверьте `errors.Is(ctx.Err(), context.DeadlineExceeded)`.

**Решение:**

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"time"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Millisecond)
	defer cancel()

	select {
	case <-time.After(100 * time.Millisecond):
		fmt.Println("done")
	case <-ctx.Done():
		if errors.Is(ctx.Err(), context.DeadlineExceeded) {
			fmt.Println("deadline")
			return
		}
		fmt.Println("canceled")
	}
}
```

## Резюме

- `context` передаёт отмену, дедлайн и request-scoped значения.
- Контекст — первый параметр, `defer cancel()` обязателен.
- `ctx.Done()` и `ctx.Err()` — стандартный способ прервать работу.

Worker pool — практическое применение горутин, каналов и WaitGroup.
