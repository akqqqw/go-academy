## Интерфейс без методов

`interface{}` не требует методов, поэтому ему удовлетворяет любой тип. С Go 1.18
есть псевдоним `any`:

```go
package main

import "fmt"

func main() {
	values := []any{42, "go", 3.14, true, []int{1, 2}}
	for _, v := range values {
		fmt.Printf("%v (%T)\n", v, v)
	}
}
```

`%T` печатает динамический тип — это первый инструмент отладки таких значений.

## Цена универсальности

Компилятор больше не знает, что внутри, поэтому нельзя вызвать методы или
арифметику напрямую. Нужен type assertion или type switch (следующие уроки).
Кроме того, значение может уйти в кучу — лишние аллокации.

Поэтому `any` используют на границах: JSON, логирование, плагины. Внутри
бизнес-логики лучше конкретные типы или дженерики (модуль 13).

## nil-ловушка

```go
var p *int
var a any = p
fmt.Println(a == nil) // false: в интерфейсе лежит тип *int
```

Интерфейс равен `nil`, только когда nil и тип, и значение. Это классический
источник багов в функциях, возвращающих `(any, error)`.

## Частые ошибки

- **Сравнение с nil.** Смотрите на `%T`, а не только на `== nil`.
- **`fmt.Sprintf("%d", a)` для any.** Без приведения будет `%!d(...)`.
- **Хранение срезов в any.** Изменения через копию интерфейса могут удивить.
- **Злоупотребление any в API.** Теряется проверка типов на компиляции.

## Практика

**Задание.** Создайте срез `[]any` из числа, строки и bool, напечатайте для каждого тип через `%T`.

**Стартовый код:**

```go
package main

import "fmt"

func main() {
	values := []any{42, "go", true}
	for _, v := range values {
		fmt.Println(v) // напечатайте тип значения через %T
	}
}
```

**Ожидаемый вывод:**

```text
int
string
bool
```

**Подсказка.** Обходите срез через `range` и печатайте `fmt.Printf("%T\n", v)`.

**Решение:**

```go
package main

import "fmt"

func main() {
	values := []any{42, "go", true}
	for _, v := range values {
		fmt.Printf("%T\n", v)
	}
}
```

## Резюме

- `any` — псевдоним `interface{}`, подходит любой тип.
- Внутри any тип известен только во время выполнения, нужен assertion.
- Интерфейс с nil-указателем внутри не равен `nil`.

Как достать конкретное значение обратно — type assertion.
