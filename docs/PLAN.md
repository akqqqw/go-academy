# План Go Academy 2.0

Порядок работ по этапам ТЗ с фактическим статусом. Отметка обновляется по мере
реализации; проверки указаны те, которые реально запускались.

## Этап 1. Аудит — готово

Отчёт: `docs/AUDIT.md`. Выводы: backend/Supabase/RLS/контент/тесты в рабочем
состоянии, критичных переделок не требуется; найдены 4 расхождения в статистике,
пробелы в light-теме и мобильной адаптивности, отсутствие офлайна, уведомлений и
мобильного приложения.

## Этап 2. Планирование — готово

- Целевая архитектура: `docs/ARCHITECTURE.md`.
- Стратегия: каталоги `backend/`, `frontend/`, `content/` не переносим (от них
  зависит `vercel.json`); общие пакеты добавляем в `packages/`; мобильное
  приложение — в `mobile/`.
- Миграции: только аддитивные (`ADD COLUMN IF NOT EXISTS`), существующие
  таблицы и идентификаторы уроков сохраняются.

## Этап 3. Web UI и согласованность статистики

- [x] Единый источник итогов в `StatsGrid`: подписи и прогресс берутся из
      `snapshot`, поле `totals` больше не подмешивается.
- [x] Кольцо «План на сегодня» показывает прогресс плана (`done/total`), а
      минуты вынесены в отдельную подпись — индикатор и список пунктов
      считаются из одного массива `snapshot.plan`.
- [x] «Пройдено тестов» на сервере считается по `COUNT(DISTINCT quiz_id)`, а не
      по числу попыток.
- [x] Проценты прогресса клампятся в 0..100 (свои карточки больше не дают 120%).
- [x] Навигация: группы «Обучение / Тренировка / Аналитика / Приложение»
      (уже были), усилены focus/hover-состояния.
- [x] Аудит light-темы: контраст всех пар «текст — фон» проверяется тестом
      `frontend/src/lib/theme-contrast.test.ts` (WCAG AA, обе схемы). По его
      результатам подняты `fg-subtle` (было 3.14:1) и `primary` в светлой теме,
      те же токены синхронизированы с мобильной темой (`mobile/src/ui/theme.ts`,
      там свой такой же тест).
- [x] Safe-area и тач-зоны мобильной веб-версии: `viewport-fit=cover`, отступы
      под вырез и home-indicator, строки навигации и кнопки ≥ 44 px до `lg`.
      Защищено тестом `frontend/src/lib/mobile-web.test.ts`.

## Этап 4a. Часовой пояс и серия дней

- [x] `APP_TIMEZONE` (по умолчанию `Europe/Moscow`): `database.Today()`,
      `database.Now()` и `database.ParseTime()` работают в поясе приложения,
      `tzdata` встроена в бинарник — на Vercel нет системных файлов зон.
- [x] Серия считается по календарным дням, а не по разнице в 24 часа: переходы
      на летнее/зимнее время её больше не обрывают (`storage.CalcStreak`).
- [x] Одинаковый пояс используется в прогрессе, достижениях, активности и
      сводке карточек.

## Ограничения окружения, влияющие на проверки

- Go SDK в песочнице отсутствует: `go test` не запускается, изменения backend
  проверяются чтением и существующими тестами в репозитории.
- Нет доступа к App Store / Play Console и нет устройства: мобильная сборка
  проверяется статически (`tsc`, конфигурация), запуск EAS — на стороне владельца.
- Публикация в сторах требует учётных данных владельца: в репозитории только
  заглушки конфигурации и инструкции.
