Дата аудита: 2026-11-05. Аудит проведён по фактическому состоянию репозитория
`akqqqw/go-academy`, ветка `arena/f930e799-go-academy`. Код на момент аудита не
менялся.

## 1. Фактическая структура

```text
go-academy/
├── backend/                    Go 1.23, net/http, pgx (Postgres) + ncruces/go-sqlite3
│   ├── cmd/server/main.go      точка входа: флаги, .env, миграции, graceful shutdown
│   ├── internal/api/           HTTP-слой: 9 файлов обработчиков, middleware, тесты
│   ├── internal/auth/          проверка access-токена Supabase + кэш на минуту
│   ├── internal/config/        флаги/окружение/.env, serverless-режим (VERCEL=1)
│   ├── internal/contentfs/     встраивание content/ в бинарник для Vercel (go:embed)
│   ├── internal/course/        чтение course.json, front matter уроков, extras

│   ├── internal/progress/      Snapshot, серия дней, план на сегодня
│   ├── internal/runner/        запуск Go-кода и go test в подпроцессе
│   ├── internal/static/        раздача SPA
│   ├── internal/storage/       ~15 хранилищ (settings, activity, notes, cards…)
│   └── vendor/                 зависимости в репозитории (офлайн-сборка)
├── content/                    104 урока (md), course.json, 30 задач, 12 колод, 6 викторин
├── frontend/                   React 19 + TS, Vite 7, Tailwind 4, TanStack Query, Zustand
│   └── src/                    94 файла: pages, features, components, lib, store, services
├── docs/vercel.md              чек-лист деплоя
├── scripts/                    dev.sh, build.sh
├── vercel.json                 два сервиса: backend (Go) и frontend (Vite)
└── Makefile, README.md
```

Итого: 1 Go-модуль, 1 фронтенд-пакет, контент отдельно от кода. Монорепозитория с
пакетами пока нет, мобильного приложения нет.

## 3. Что требует исправления

### 3.1 Согласованность статистики (реальные расхождения)

1. **«Пройдено тестов» считает попытки, а не тесты.** В
   `progress.Snapshot` запрос `(SELECT COUNT(*) FROM quiz_attempts WHERE total > 0)`
   даёт число попыток; при повторном прохождении одного теста счётчик растёт,
   хотя «пройдено тестов» должен оставаться 1. Нужен `COUNT(DISTINCT quiz_id)`.
2. **Процент карточек может превысить 100%.** Числитель — `COUNT(DISTINCT card_id)`
   по всем повторениям (включая свои карточки), знаменатель — число карточек из
   контента. Пользователь со своими карточками получает «120%».
3. **Два источника итогов на главной.** `StatsGrid` берёт подписи «из N» из
   `totals` (данные контента), а прогресс-бар — из `snapshot`, где `total` тоже
   из контента, но при рассинхроне источников подпись и полоса расходятся.
   Нужно одно поле-источник.
4. **Кольцо «План на сегодня» показывает минуты, а подпись — число задач.**
   `ProgressRing` заполняется по минутам (`today_minutes / goals.minutes`),
   рядом написано «Выполнено 2 из 4» — две разные метрики в одном индикаторе,
   из-за чего кольцо «не сходится» с пунктами плана.

### 3.2 Тема и адаптивность

- Тема `light` реализована токенами, но проверялась только точечно: часть
  компонентов использует захардкоженные цвета (`#00758f`, `text-white`,
  inline-подсветка кода). Нужен аудит на светлой теме.
- Нет `prefers-reduced-motion` для новых анимаций (есть только класс
  `reduced-motion` из настроек).

### 3.3 Мобильная веб-версия

- SPA адаптивна по сетке, но: нет safe-area (вырез/жесты iOS), кнопки в редакторе
  и на странице урока мелкие (меньше 44 pt), боковое меню на телефоне требует
  отдельного жеста «бургер» без нижней навигации.
- Monaco на телефоне неудобен как основная среда (виртуальная клавиатура
  перекрывает код) — это ограничение не лечится CSS.

### 3.4 Безопасность и лимиты

- `runner` запускает код подпроцессом с таймаутом и лимитом вывода, но **без
  изоляции** (тот же пользователь ОС, общий `/tmp`, сеть доступна). Документация
  это честно указывает; для публичного сервиса нужен отдельный sandbox
  (см. `docs/CODE_RUNNER.md`).
- Нет rate limiting на `/api/editor/run`, `/api/exercises/{id}/submit` —
  злоупотребление возможно при появлении публичного аккаунта.
- Нет CSRF-проблемы (Bearer-токены), но нет идемпотентного ключа для повторной
  отправки решения при обрыве сети.

### 3.5 Прочее

- Нет офлайн-режима: без интернета веб не отдаёт даже контент уроков.
- Уведомлений нет (ни web push, ни нативных).
- Нет OAuth (Google/Apple).

## 5. Потенциально опасные изменения (риски)

| Изменение | Риск | Решение |
| --- | --- | --- |
| Перенос `frontend/` и `backend/` в `apps/` | ломает `vercel.json`, скрипты, Makefile, go-тест деплоя, историю CI | **не переносим**: оставляем каталоги на месте, общие пакеты добавляем рядом в `packages/` |
| Полный переход на npm workspaces | меняет lock-файл, ломает `npm ci` на Vercel | не переводим; пакеты подключаем как исходники через alias (web) и metro watchFolders (mobile) |
| Переписывание API на «целевую» схему БД | потеря существующего прогресса пользователей | не переименовываем существующие таблицы; изменения только аддитивные (миграции `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`) |
| Замена SM-2 на FSRS | сброс расписания повторений у пользователей | оставляем SM-2 (сервер), выносим формулу в shared-learning для единообразия, FSRS — отдельным решением владельца |
| Замена Monaco на CodeMirror в web | ухудшение UX, регресс тестов | не меняем; на mobile — отдельный редактор, не WebView с Monaco |
| Единый «источник правды» прогресса | двойной учёт при офлайне | сервер остаётся источником правды, клиент — локальный кэш + журнал изменений |

## 6. Вывод

Проект в рабочем состоянии и ближе к ТЗ, чем предполагалось: backend, схема,
RLS, контент и тесты уже есть. Критичных архитектурных переделок не требуется.
Работа сводится к:

1. аддитивным исправлениям статистики и UI (web);
2. выделению общих пакетов без изменения текущего деплоя;
3. новому каталогу `mobile/` (Expo) с реальной интеграцией через существующий API;
4. офлайн-кэшу и очереди синхронизации на мобильном;
5. документации и подготовке релиза.

Порядок и объём этапов — в `docs/PLAN.md`, целевая архитектура — в
`docs/ARCHITECTURE.md`.
