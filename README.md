# 🚀 Go Academy

Локальная платформа для самостоятельного изучения **Go**: программа из 14 модулей,
личная статистика, дневные цели и календарь активности. Работает офлайн, без
регистрации, аккаунтов и платных API. Все данные лежат в SQLite на вашем компьютере.

> **Текущий статус: этапы 1–4 завершены — основа приложения, 15 полноценных
> уроков, встроенный редактор с настоящим запуском Go-кода и 30 практических
> задач с проверкой через `go test`.** Этапы 5–10 (заметки, карточки, тесты)
> реализуются последовательно; разделы, которые ещё не готовы, честно сообщают об
> этом и не содержат фиктивных кнопок. Подробнее — в разделе
> [Дорожная карта](#дорожная-карта).

## Технологии

**Frontend:** React 19, TypeScript, Vite 7, Tailwind CSS 4, компоненты в стиле
shadcn/ui (Radix UI), Zustand, TanStack Query, React Router 7, Lucide Icons, Sonner.
Тесты — Vitest + Testing Library.

**Backend:** Go (стандартная библиотека `net/http`, `log/slog`), SQLite через
[`github.com/ncruces/go-sqlite3`](https://github.com/ncruces/go-sqlite3) —
SQLite скомпилирован в WebAssembly, поэтому **cgo и системные библиотеки не нужны**.

## Быстрый старт

Требования:

- **Go 1.23+** (проверено на Go 1.27),
- **Node.js 20+ и npm**,
- браузер (Chrome, Firefox, Safari, Edge).

```bash
git clone <репозиторий> go-academy
cd go-academy

# один раз — зависимости фронтенда
npm --prefix frontend install

# запуск backend + Vite в dev-режиме
make dev
```

- Интерфейс: **http://localhost:5173** (Vite проксирует `/api` на backend).
- API: **http://127.0.0.1:8080/api**.

Без Make:

```bash
# терминал 1
cd backend && go run ./cmd/server --data ../data --content ../content

# терминал 2
cd frontend && npm run dev
```

## Продакшн-запуск на одном порту

```bash
make build      # фронтенд → frontend/dist, backend → backend/bin/go-academy
make run        # соберёт и запустит на http://127.0.0.1:8080
```

Либо вручную:

```bash
cd frontend && npm run build
cd ../backend && go build -o bin/go-academy ./cmd/server
./bin/go-academy --data ../data --content ../content --frontend ../frontend/dist
```

Backend отдаёт собранный SPA, поддерживает клиентскую маршрутизацию (fallback на
`index.html`) и JSON-ошибки для неизвестных `/api`-маршрутов (404/405).

Учебный контент отделён от кода: программа курса лежит в `content/course.json`,
уроки — Markdown-файлы в `content/lessons/<модуль>/<урок>.md`. Приложение читает
программу при старте; кнопка «Перечитать контент» в настройках перезагружает
каталог без перезапуска сервера, а тексты уроков читаются с диска при каждом
открытии — правки видны сразу.

### Формат файла урока

Front matter — это JSON между двумя строками `---`, затем обычный Markdown с
поддержкой таблиц (GFM) и блоков кода ` ```go `:

```markdown
---
{
  "title": "Что такое Go",
  "summary": "Короткое описание для карточки урока.",
  "minutes": 10,
  "objectives": ["Первая цель", "Вторая цель"]
}
---
## Теория

Текст урока с примерами:

```go
package main

import "fmt"

func main() {
	fmt.Println("Привет")
}
```

## Практика

Задание, стартовый код, ожидаемый вывод и подсказка.

## Резюме

- Ключевой вывод урока.
```

Обязательны `title`, хотя бы одна цель и непустой текст; остальные поля
подставляются из `course.json`. Проверки в Go-тестах требуют, чтобы каждый
готовый урок содержал разделы «Практика» и «Резюме» и блок кода. Некорректный
файл не ломает сервер: API вернёт `content_invalid` с понятным сообщением.

## Практика и проверка решений

### Формат задания

```
{
  "id": "sum-two",
  "module": "m02",
  "title": "Сумма двух чисел",
  "summary": "Арифметика, параметры и возвращаемое значение.",
  "difficulty": "easy",
  "topics": ["операторы", "функции"],
  "minutes": 5,
  "statement": "## Условие\n…Markdown…",
  "starter_code": "package main\n\nfunc Sum(a, b int) int { … }",
  "hints": ["Сложение двух int работает напрямую."],
  "solution": "package main\n…эталон…",
  "tests": "package main\n\nimport \"testing\"\n\n// TestSumPositive складывает…\nfunc TestSumPositive(t *testing.T) { … }"
}
```

Заголовок проверки берётся из комментария перед функцией `Test*` — именно он
показывается ученику вместо имени теста. Файл проверяется при загрузке: известен
ли модуль, уникален ли `id`, есть ли тесты, подсказки и эталонное решение.

Задания лежат отдельно от кода — в `content/exercises/exercises.json`. Каждое
задание содержит условие в Markdown, стартовый код, подсказки, эталонное
решение и файл Go-тестов. **Тесты и решение в браузер не отправляются**: иначе
проверку можно было бы обойти, подогнав ответ под конкретные assert-ы.

| Что | Где |
| --- | --- |
| Каталог заданий и проверка контента | `backend/internal/practice` |
| Запуск проверок | `backend/internal/runner/grade.go` (`go test -json`) |
| История попыток в SQLite | `backend/internal/storage/exercises.go`, таблица `exercise_attempts` |
| Список с фильтрами и статистикой | `frontend/src/pages/practice-page.tsx` |
| Страница решения | `frontend/src/pages/exercise-page.tsx` |
| Панель результатов | `frontend/src/components/editor/test-results.tsx` |

Как устроена проверка:

1. решение и файл тестов пишутся в отдельный временный каталог (`main.go`,
   `exercise_test.go`);
2. запускается `go test -json -count=1 -timeout <лимит> main.go exercise_test.go`;
3. поток разбирается как JSON: `pass`/`fail` приходят по каждому тесту, а всё,
   что программа печатает сама, попадает в поле `Output` — подделать «PASS»
   текстом нельзя;
4. результат сопоставляется со списком ожидаемых тестов: если тест не
   отчитался (например, программа вызвала `os.Exit`), проверка не засчитывается;
5. ошибки сборки приходят событиями `build-output`/`build-fail` и превращаются в
   диагностики с номерами строк основного файла.

Дополнительно проверяются ресурсные лимиты (таймаут, размер вывода, очередь
запусков) и запрет `os/exec` — как и для свободного редактора. Первое успешное
решение увеличивает дневной счётчик решённых задач и попадает в план на сегодня;
повторные прохождения счётчик не трогают.

Содержание курса проверяется тестами: `TestRepositoryExercisesAreSolvable`
компилирует стартовый код каждого задания и прогоняет его тесты на эталонном
решении — так контент не может «сломаться» незаметно.

## REST API

Все ответы — JSON, ошибки имеют единый формат:

```json
{ "error": { "code": "validation_error", "message": "…", "details": [ … ] } }
```

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/health` | Живость сервера и версия |
| `GET` | `/api/meta` | Версия, этап, окружение, размер базы, состав контента |
| `GET` | `/api/dashboard` | Сводка главной: прогресс, план, «продолжить», активность |
| `GET` | `/api/course` | Программа курса с прогрессом модулей |
| `POST` | `/api/content/reload` | Перечитать каталог `content/` |
| `GET` | `/api/lessons/{id}/content` | Текст урока: Markdown, цели, контекст модуля, соседние уроки |
| `GET` | `/api/lessons/{id}` | Сохранённый статус урока |
| `POST` | `/api/lessons/{id}/opened` | Зафиксировать открытие урока |
| `POST` | `/api/lessons/{id}/completed` | Отметить урок пройденным (идемпотентно) |
| `GET` | `/api/editor/status` | Доступность Go SDK, версия, лимиты, предупреждение об изоляции |
| `POST` | `/api/editor/run` | Собрать и запустить код: статус, stdout/stderr, время, диагностики |
| `POST` | `/api/editor/check` | Только компиляция, без запуска |
| `POST` | `/api/editor/format` | Форматирование `gofmt` или ошибки разбора |
| `GET` | `/api/drafts` | Черновики кода и последние запуски |
| `GET`/`PUT`/`DELETE` | `/api/drafts/{key}` | Черновик кода: `editor`, `lesson-<id>`, `exercise-<id>` |
| `GET` | `/api/exercises` | Задания с фильтрами `difficulty`, `module`, `status`, `q` |
| `GET` | `/api/exercises/{id}` | Условие, стартовый код, подсказки, список проверок, история попыток |
| `POST` | `/api/exercises/{id}/submit` | Проверка решения настоящими `go test`: результат по каждой проверке |
| `GET` | `/api/exercises/{id}/solution` | Эталонное решение (интерфейс спрашивает подтверждение) |
| `GET` | `/api/progress` | Полная статистика обучения |
| `GET` | `/api/activity?days=182` | Активность по дням, серия, суммарное время |
| `POST` | `/api/activity/study` | Добавить время обучения (`seconds` ≤ 900) |
| `GET` | `/api/activity/recent` | Лента последних действий |
| `GET` | `/api/settings` | Настройки и их описания |
| `PATCH` | `/api/settings` | Частичное обновление с валидацией (422 при ошибке) |
| `GET` | `/api/search?q=` | Глобальный поиск по модулям, урокам и разделам |
| `GET` | `/api/backups` | Список резервных копий |
| `GET` | `/api/backup` | Создать копию и скачать файл |

Примеры:

```bash
curl http://127.0.0.1:8080/api/dashboard

curl -X POST http://127.0.0.1:8080/api/lessons/m01-01/opened
```

Проверка настроек строгая: неизвестные ключи, неверные типы и значения вне
диапазона отклоняются целиком, ничего не записывается. Конфигурация белого
списка полей активности не позволяет подставить SQL из HTTP-слоя.

## Данные, резервные копии и офлайн-режим

- База: `data/academy.db` (SQLite, режим WAL). Каталог `data/` создаётся сам.
- При каждом запуске сервера создаётся резервная копия в `data/backups/`,
  хранятся 5 последних. Копию также можно скачать из «Настроек» (это делает
  консистентный `VACUUM INTO`, а не копирование файла).
- Миграции применяются по одной и записываются в `schema_migrations`; обновление
  приложения не удаляет пользовательские таблицы.
- Время обучения учитывается только при активной вкладке (heartbeat раз в
  минуту, скрытая вкладка не считается).
- Прогресс уроков, настройки и серия дней восстанавливаются после перезапуска.
- Сброс данных: остановить сервер и удалить `data/` (копии сохраните заранее).

**Офлайн.** Backend собирается из `backend/vendor` без интернета. Фронтенд после
`npm install` работает только с локальными файлами: нет Google Fonts, CDN,
телеметрии и внешних API. Шрифты — системный стек, иконки — пакет `lucide-react`.

## Безопасность запуска кода

Код собирается и запускается локально (`backend/internal/runner`):

| Ограничение | Как реализовано |
| --- | --- |
| Временный каталог | `os.MkdirTemp` внутри `data/tmp`, удаляется после запуска |
| Лимит времени | Контекст с таймаутом (`--run-timeout`, по умолчанию 10 с); процесс убивается вместе с потомками |
| Лимит вывода | Не более 256 КБ на поток; при переполнении процесс останавливается, вывод помечается как обрезанный |
| Лимит исходника | 256 КБ кода на запуск |
| Сборка и запуск | Сначала `go build` (ошибки компиляции отделены от выполнения), затем прямой запуск бинарника — без `sh -c` |
| Окружение | `GOPROXY=off`, `GOTOOLCHAIN=local`, `GOWORK=off`, `CGO_ENABLED=0`, общий кеш сборки, `HOME` и `TMPDIR` указывают во временный каталог |
| Очередь | Не более 2 одновременных запусков, остальные ждут свободный слот 15 с и получают понятную ошибку |
| Запрет оболочки | Импорт `os/exec` и `plugin` отклоняется до компиляции: из интерфейса нельзя запустить внешнюю команду |
| Поиск `go` | Проверяется, что найденный файл — настоящий бинарник (ELF/Mach-O/PE), а не скрипт-обёртка |
| Проверка решений | `go test -json` в том же временном каталоге; ожидается отчёт по каждому тесту, иначе решение не засчитывается |

**Важно:** локальный запуск Go-кода **не является полноценной песочницей** — процесс
имеет те же права, что и пользователь, и может читать файлы. Для исполнения
недоверенного кода нужна изоляция: контейнер без сети, с лимитами CPU и памяти,
read-only файловой системой и минимальными правами. Приложение пишет об этом и
в разделе «Редактор», и под редактором в уроке, а не обещает «полную
безопасность».
